CBA — Colorblind Assistant

personal project · ongoing · React Native (Expo) · repo

An app for colorblind people (like me). It started as a cooking thing: point your camera at food and it tells you if it's done, so you're not squinting at chicken trying to figure out if it's still pink. Then I realized getting dressed has the exact same problem, so now it's mostly a wardrobe and outfit app. Anything color-related always comes with a text label too, never just a color.

What it does

  • Food & clothes checkers: snap a photo, get a verdict (done or not, match or clash) from a vision model running on Cloudflare Workers AI
  • Wardrobe: scan your clothes and they get tagged automatically (color, style, pattern, fit). You can fix the tags if it gets something wrong, throw stuff in the laundry so it's skipped, and save outfits you like
  • Outfit generator: pick a vibe (casual, formal, beachwear, etc.) and the temperature, and it puts together a full outfit plus a tip on how to wear it
  • Personalization: take a selfie and fill in a couple things (height, build) and it leans toward stuff that suits you. It only ever gives bonuses relative to you as a person, never "this looks bad on you," because nobody wants their app judging them

How it works

  • Outfit generation used to be an AI prompt. After a bunch of testing on my phone it kept making up colors and forgetting to include pants, so I ripped it out and wrote a rules engine instead. It goes through every possible outfit in your closet, scores each one, and picks the best
  • The scoring checks color clashes, patterns, light/dark balance, style, weather, layering, and makes sure you don't end up wearing two hats (that happened). The clash list, as well as most style choices were researched, crossrefrenced between each other, and hand-picked for best results, since color theory says red + green is a great combo and... no
  • AI still does the parts it's actually good at, like tagging a photo, but I clean up and check what it gives back before trusting it
  • 21 ADRs covering every big decision, including the ones I changed my mind on
  • 314 tests, TypeScript with zero errors

Takeaway

  • Asking an AI nicely isn't the same as making sure something happens. The app got better every time I moved a role out of a prompt and into actual code.

Tech

  • TypeScript, React Native, Expo, Cloudflare Workers AI, Jest

ADR Manager — TC Annotation addition

CS 4530 Summer School · VS Code extension · open source · marketplace · repo

I was the data layer person on a 5-track team building a VS Code extension for managing Architectural Decision Records. Designed the TypeScript interfaces the whole team built against, wired up the YAML read/write, and spent an unreasonable amount of time making sure a grammar migration from another track didn't silently break mine. I then transitioned into a role that required me to merge all tracks, polish any bugs, and extend a couple of features to publish a well developed product.

  • Designed TcAnnotation and all enum types (TcCategory, TcSignal, TcStatus) as the shared contract across the full team
  • Built parseTcFromYaml() and serializeTcToYaml(), reads and writes annotation fields from YAML frontmatter without corrupting anything else in the file
  • Built validateTcAnnotation(), validates all 6 field types and returns per-field error messages consumed by the UI layer
  • Mode-aware serialisation: pro-only fields only written when professional editor is active
  • Schema version stamping and real-world compatibility testing against JabRef's 60-file ADR corpus
  • 82 tests across 4 suites, including fixing all fixture breakage when Track A migrated the grammar mid-project

Tech

  • TypeScript, js-yaml, ANTLR4, Jest, VS Code Extension API
